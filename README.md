# 背单词练习 · 随机抽练

一个**零依赖、纯本地运行**的背单词工具。录入英文单词，由大模型（DeepSeek）校验拼写、识别词性并自动翻译中文；练习时随机抽词，看中文输入英文，自动判分并记录对错次数。

---

## 1. 解决了什么问题

自己整理单词表背单词时，通常要跨三个工具来回切：

| 麻烦 | 本项目的做法 |
| --- | --- |
| 抄来的词表里混着拼错的词、乱码，得一个个去查证 | 录入时由大模型**先校验是否是真的英文单词**，拼错的直接拦下，不会污染词库 |
| 查词性、查中文释义要开词典网站，一次只能查一个 | 一次请求**批量**处理整份词表，自动补全词性和中文，几十个词几秒钟搞定 |
| 背单词 App 要么收费，要么把词库锁在它的账号里，还夹广告 | 单文件、无依赖、完全离线运行；**词库存在你自己的浏览器里**，不注册不联网也能练 |
| 只知道自己"错了"，不知道错在哪、哪些词反复错 | 每个词记录 ✓ 答对 / ✗ 答错次数，练习结束单独列出答错的词，支持一键只重练错题 |

一句话：**把"整理词表 → 记忆 → 检验"压缩进一个本地网页，不用注册、不用装软件、数据不出本机。**

## 2. 主要功能

### 词库管理
- **单条录入**：输入英文 → 自动校验 + 出词性 + 译中文；中文框填了就以你填的为准
- **批量录入**：整行粘贴词表，一次 API 调用处理全部（上限 120 词/批）
- **词库列表**：显示对错统计、录入日期，支持编辑、删除、按录入时间 / 字母排序

### 练习模式
- 滑块选择每次抽取数量（1–50）
- 看**中文 + 词性**，输入对应英文
- 实时判分，答完全局得分环 + 答错词清单
- 「再练一遍」「只练答错的」「调整设置」；点单个错词可单独重练它
- 练习页底部有**积分累计器**：词库加分、答题加分、整轮全错扣分一目了然

### 积分规则

| 事件 | 积分变化 |
| --- | --- |
| 词库新增 1 个单词 | **+0.1** |
| 练习每答对 1 题 | **+1** |
| 一整轮练习**全部答错** | **−5**（每轮只扣一次） |
| 总分下限 | **0**（不会出现负分） |

- 改答案后重新判定，答对分按**最后一次**结果算，不会重复加分
- 删词不扣已得的词库分；重复录入同一个词不重复加分
- 积分存在本机 `localStorage`（键名 `wp-points`），刷新、关浏览器都不丢
- 首次启用会按现有词库一次性补记（0.1 × 当前词数）

### 运行方式
- **零依赖**：不用 `npm install`，Node 18+ 直接跑
- **双模式**：配了 DeepSeek Key 走大模型；没配则自动回退免费词典接口（dictionaryapi.dev + MyMemory）
- **局域网共享**：服务监听 `0.0.0.0`，手机连同一个 Wi-Fi 扫码即用；词库 / 积分 / Key 存在电脑的 `data.json` 里，多设备实时同步
- **也是 PWA**：同一份 `index.html` 可直接静态托管，手机浏览器打开就能用，可「添加到主屏幕」并离线使用

## 手机扫码：和电脑共用同一份词库（同一个 Wi-Fi）

在家 / 宿舍（手机和电脑连同一个 Wi-Fi）时，不用装 App、不用注册，扫码就能用电脑上的数据：

1. 电脑上双击 `start.bat` 启动服务；
2. 打开 <http://127.0.0.1:8111>，进【设置】→「手机扫码连接」，会显示二维码和局域网地址；
3. 手机连同一个 Wi-Fi，用相机扫码（或直接输入这个地址），浏览器打开即用。

- 手机上加的词、练习记录、积分会**实时同步**到电脑（约 4 秒内），电脑上改的也会同步回手机；
- DeepSeek API Key 存在电脑的 `data.json` 里，手机端不用再填；
- 电脑退出服务或离开这个 Wi-Fi 就打不开了（数据仍然在电脑上）。

### 打不开？按顺序排查

1. 手机和电脑是否连的是**同一个** Wi-Fi（电脑插网线、手机连 Wi-Fi 一般也可以）；
2. Windows 防火墙：以管理员身份运行一次 **`允许手机访问.bat`**（放行 TCP 8111，专用网络）；
3. 校园网 / 酒店 / 公共 Wi-Fi 常有「AP 隔离」，设备之间无法互访 —— 改用手机热点或家用路由器；
4. 电脑有多块网卡时，二维码用的是默认出口网卡，页面上的「备用地址」可以直接点开试试。

### 安全说明

- 服务监听局域网端口，但只接受「本机地址 / 本机局域网 IP」的 Host 与 Origin（防 DNS rebinding 和恶意网页调用），隐藏文件与 `data.json` 不会被下载；
- 同一 Wi-Fi 下的设备能读写词库，也能用你保存的 DeepSeek Key 额度，建议只在家用网络开启；
- `data.json`（词库 + 积分 + Key）已加入 `.gitignore`，删掉它等于重置全部数据。

## 3. 安装方法

**前置条件**：安装 [Node.js](https://nodejs.org/) 18 或更高版本（自带 `fetch`，本项目在 Node 24 下开发测试）。

```powershell
# 1. 确认 Node 版本
node -v          # 应输出 v18.x 或更高

# 2. 进入项目目录（不用 npm install，本项目零第三方依赖）
cd word-practice

# 3. 启动
node server.js
```

Windows 用户可直接**双击 `start.bat`**：它会自动启动服务并打开浏览器，关掉那个命令行窗口即停止服务。

启动成功后终端会输出：

```
背单词练习运行中:  http://127.0.0.1:8111
DeepSeek 校验服务已就绪（Node v24.15.0）
```

### （可选）配置 DeepSeek API Key

不配也能用，但配了之后批量导入只发 **1 次**请求，速度快、校验准。配置步骤：

1. 打开 [platform.deepseek.com](https://platform.deepseek.com) → **API Keys** → 创建
2. 页面顶部 **【设置】** 标签 → 粘贴 Key → 「保存」→「测试连接」

Key 只存在你自己浏览器的 `localStorage`，经本机服务转发，服务端不留存。

## 4. 使用方法

### 第一步：录入单词

切到 **【词库】** 标签，两种方式任选：

- **单条**：英文框输入 `butterfly`，中文框留空 → 点「识别并添加」
- **批量**：把整份词表粘进文本框，每行一个词 → 点「联网批量导入」

### 第二步：开始练习

1. 切到 **【练习】** 标签
2. 拖动滑块选择本次抽取数量（如 20 个）
3. 点「开始抽练」
4. 屏幕显示**中文 + 词性**，在输入框敲出对应英文，按 **回车** 判定；判定后输入框不锁定，改完答案再按回车会重新判定
5. 判定后再按一次**回车**（连按两次回车）直接进入下一题，不用点鼠标；答完所有题后查看得分，可点「只练答错的」专攻错题

### 可用操作速查

| 位置 | 操作 |
| --- | --- |
| 词库列表 | ✏️ 编辑（改英文/中文）、🗑️ 删除 |
| 词库顶部 | 「按录入排序」/「按字母排序」切换、「清空」 |
| 练习答题 | 回车判定；判定后仍可修改答案，再回车重新判定；连按两次回车直接进入下一题 |
| 积分累计器 | 练习页底部；答对时右上角飘 `+1`，全错触底时飘扣分 |
| 结果页 | 「再练一遍」「只练答错的」「调整设置」 |

## 5. 输入输出示例

### 示例 A：批量录入

**输入**（粘贴到「批量录入」文本框，每行一个，中英文用空格 / Tab / 冒号分隔）：

```
apple 苹果
delicious
rapidly 迅速地
butterflly
```

**输出**（页面提示）：

```
✅ 成功 3 / 4
❌ 失败 1：butterflly(查不到)
```

词库中新增 3 条 —— 注意第 4 行是故意拼错的 `butterflly`，被校验拦下，**不会进词库**：

| 英文 | 词性 | 中文 |
| --- | --- | --- |
| apple | n. | 苹果 |
| delicious | adj. | 美味的 |
| rapidly | adv. | 迅速地 |

> `delicious` 这行没写中文，输出里自动补上了「美味的」；`apple`、`rapidly` 则使用你手填的中文。

### 示例 B：单条录入

**输入**：英文框 `butterfly`，中文框留空 → 点「识别并添加」

**输出**：

```
✅ 已录入 butterfly · [n.] 蝴蝶
```

**失败时**（输入 `asdfgh`）：

```
❌ 单词录入失败：大模型判定 "asdfgh" 不是有效英文单词  [仍手动添加]
```

### 示例 C：练习答题

**输入**（屏幕显示中文，你输入英文）：

```
请说出对应的英文
        蝴蝶
        [n.]
┌─────────────────────┐
│  butterfly          │  ← 你输入的内容
└─────────────────────┘
```

**输出**：

```
✅ 正确！
butterfly
```

答错时：

```
❌ 不对，正确是
butterfly
你写的是：butterly
```

全部答完后：

```
        85         答对 17/20 · 85%

答错的（点击可单独再练）
[butterfly 蝴蝶]  [ancient 古代的]  [rapidly 迅速地]

本次抽取的词库
[n. apple]  [adj. delicious]  ...
```

### 示例 D：后端 API（`POST /lookup`）

如果你想绕过界面直接调用本机服务：

**请求**

```http
POST http://127.0.0.1:8111/lookup
Authorization: Bearer sk-你的DeepSeek-Key
Content-Type: application/json

{"words": ["apple", "delicious", "asdfgh"]}
```

**成功响应** `200`

```json
{
  "results": [
    { "word": "apple",     "valid": true,  "pos": "n.",  "zh": "苹果",     "reason": "ok" },
    { "word": "delicious", "valid": true,  "pos": "adj.", "zh": "美味的",  "reason": "ok" },
    { "word": "asdfgh",    "valid": false, "pos": "",    "zh": "",        "reason": "invalid" }
  ]
}
```

`results` 的顺序和长度**始终与请求的 `words` 一一对应**（服务端做了对齐处理，即使模型漏词或改了大小写）。

**错误响应**

| 状态码 | `error` | 含义 |
| --- | --- | --- |
| `401` | `no-key` | 请求头没带 Key |
| `401` | `auth` | Key 无效，被 DeepSeek 拒绝 |
| `429` | `quota` | 余额不足或请求过频 |
| `400` | `bad-request` | 没有有效单词 |
| `502` | `upstream` | DeepSeek 返回了其它错误 |

```json
{ "error": "no-key", "message": "尚未设置 API Key，请在【设置】里填写" }
```

**限制**：单次最多 120 个词，单个词最长 80 字符。

## 工作原理

```
本地 / 局域网模式（http://127.0.0.1:8111 或 http://192.168.x.x:8111）
浏览器 (index.html)
   │  1. 前端把待校验的单词数组 POST 到 /lookup
   │     Header: Authorization: Bearer <你的 DeepSeek Key>（手机可省略，用电脑上存的）
   │  2. 前端读 /state 拿词库+积分；每次改动 POST /state（带 rev 版本号，冲突返回最新数据）
   ▼
本地服务 (server.js) ── data.json（原子写入）
   │  3. 服务取出 Key，组装成一次 chat/completions 请求
   ▼
DeepSeek API
   │  4. 返回 JSON：{ results:[{word, valid, pos, zh}, ...] }
   ▼
本地服务按原始单词顺序对齐结果 → 返回前端

两台设备之间：每 4 秒 GET /state?since=rev，rev 变了就整页刷新词库与积分。

静态托管模式（手机 / GitHub Pages）
浏览器 (index.html)
   │  1. 前端直接 POST api.deepseek.com/chat/completions（CORS 已由 DeepSeek 支持）
   │  2. 前端自己做结果对齐（alignResults）
   └─ 3. Service Worker 缓存页面，断网也能打开
```

局域网模式下来自局域网的 `/lookup` 不要求 Key（用电脑上保存的那一个），其它接口只对本机/局域网白名单 Host 开放。

## 常见问题

**启动时提示端口被占用**
改环境变量换端口即可，前端会自动跟随当前端口：
```powershell
$env:PORT = 8112; node server.js
```
注意：本机 8000 端口常被酷狗音乐的后台服务占用，本项目默认用 8111 正是为了避开它。

**页面显示「本机服务未运行」**
说明 `server.js` 没起来，或被防火墙拦了。确认命令行窗口还在、没报错。此时大模型不可用，但词典回退仍能工作。

**提示「API Key 无效」/「额度不足」**
- `401` → Key 填错了或已失效，去 DeepSeek 后台重新建一个
- `402 / 429` → 余额不足或请求太频繁，充值 / 等一会儿再试

**词库录入不进我给的词**
DeepSeek 判定它不是真实英文单词（拼写错误或乱码）时会拒绝录入。确实要加可以点提示里的「仍手动添加」（但必须自己填中文）。

**换了台电脑 / 换了浏览器，词库空了**
共享的数据在电脑的 `data.json` 里：换浏览器不影响，手机扫码也能拿到同一份。只有静态托管版（GitHub Pages）是各设备独立存在浏览器里的。

**关掉窗口后词库会丢吗**
不会。电脑版写在 `data.json`，静态托管版存在浏览器 localStorage，都跟服务进程无关。

## 隐私与安全

### 网络攻击面

服务监听 `0.0.0.0`（否则手机连不上），但只接受**白名单 Host**：`127.0.0.1`、`localhost`、本机网卡 IP + 端口；用域名（含 DNS rebinding 的恶意域名）访问一律 `403`。需要防的是本机/局域网浏览器发起的攻击：

| 攻击手法 | 防护措施 |
| --- | --- |
| **DNS rebinding**：诱导你打开恶意网页，该网页把域名解析到本机 IP 来访问服务 | 校验 `Host` 请求头，只接受本机地址 / 本机网卡 IP + 当前端口，其余一律 `403` |
| **跨站调用**：任意网页用 `fetch` 调你的接口，消耗你的 DeepSeek 额度 | 校验 `Origin` 请求头，非本机/局域网来源（含 `null` / 沙箱 iframe）一律 `403` |
| **目录穿越**：`GET /../../Windows/win.ini` 读取项目外的文件 | 路径规范化 + 目录前缀校验，越界返回 `403` |
| **偷看数据**：直接下载 `data.json` 或 `.git/` 里的内容 | 隐藏文件（`.` 开头）与 `data.json` 一律 `404` |
| **超大请求体**：塞入巨量数据撑爆内存 | 请求体上限 2 MB，超出返回 `413` |
| **连接占用**：慢速发请求把连接拖住 | 请求头 20s / 整体请求 120s / 请求头数量 100 条上限 |
| **MIME 嗅探 / 点击劫持 / 信息外泄** | 所有响应带 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer` |

### 你的 API Key

- Key 存在**浏览器** `localStorage`（key 名 `wp-deepseek-key`），设置页保存时**同时**写进电脑的 `data.json`，这样手机扫码后不用重复填写
- 服务端**不记录请求日志**，只在 `/lookup` 转发时使用 Key；手机端请求可以不带 Key，由电脑代填
- 词典回退路径（`dictionaryapi.dev` / `mymemory`）**只发送单词本身，不带 Key**
- ⚠️ Key 明文存放，**任何能在这台电脑上用这个浏览器的人都能读取** → 不要在公用电脑上保存 Key
- ⚠️ 局域网共享开启时，**同一 Wi-Fi 下的设备可以用你的 Key 额度**（它们看不到 Key，但能触发请求）→ 建议只在家用网络开启
- ⚠️ `localStorage` 按「协议+主机+端口」隔离。若有**别的程序也占用了 8111 端口**，它的页面与本站同源，理论上能读到你的 Key。建议保持 8111 空闲，或换用不常用端口

### 其他

- `start.bat` 里的路径全部用 `%~dp0` 相对定位，整个文件夹拷到任何位置都能直接跑
